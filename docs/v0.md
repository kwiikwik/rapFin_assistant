# v0 — baseline

Première version complète du pipeline : extraction → chunks → recherche hybride → génération avec citations → interface Streamlit.
Objectif : avoir un système de bout en bout **mesuré**, pour améliorer ensuite une brique à la fois.

## Configuration

| Brique | Choix v0 |
|---|---|
| Extraction | `pymupdf4llm` (Markdown par page), images et pieds de page retirés, nettoyage léger (balises, ligatures) |
| Chunking | `RecursiveCharacterTextSplitter`, 1 500 caractères, chevauchement 200 → 5 840 chunks |
| Dense | `BAAI/bge-m3` (multilingue, 1 024 dim.) + Chroma, distance cosinus |
| Sparse | BM25 (`rank_bm25`), tokenisation FR/EN maison (accents, nombres, mots vides), classe LangChain `BM25Retriever` maison |
| Fusion | Reciprocal Rank Fusion (`EnsembleRetriever`), 10 candidats par retriever, poids BM25/dense = 0,3/0,7 |
| Contexte LLM | 5 extraits numérotés `[n] (banque, fichier, page)` |
| LLM | `openai/gpt-oss-120b` via Groq (gratuit), `temperature=0`, `reasoning_effort="low"` |
| Prompt | réponse uniquement depuis les extraits, citation `[n]`, phrase de refus fixe, langue de la question, précision de l'entité |

## Jeu d'évaluation

24 questions écrites sur les 3 rapports ([`data/eval/questions.jsonl`](../data/eval/questions.jsonl)), avec pour chacune les pages qui contiennent la réponse et les valeurs clés attendues.

| Type | Nb | Exemple |
|---|---|---|
| `terme_exact` | 7 | « Quel est le ratio CET1 de BNP Paribas au 31 décembre 2025 ? » |
| `multilingue` (question FR, rapport EN) | 5 | « Quel est le ratio CET1 du groupe UBS fin 2025 ? » |
| `reformulee` | 3 | « Combien BNP Paribas a-t-il gagné en 2025 ? » |
| `tableau` | 3 | « Quelle est la taille du bilan de Crédit Agricole S.A. fin 2025 ? » |
| `nom_propre` | 3 | « Qui est le directeur général d'UBS ? » |
| `ambigu` (banque non précisée) | 2 | « Quel est le ratio CET1 ? » |
| `date` | 1 | « Quand les comptes consolidés 2025 de Crédit Agricole S.A. ont-ils été arrêtés ? » |

## 1. Retrieval

**hit@5** : la bonne page est-elle parmi les 5 premiers extraits ? **MRR** : moyenne de 1/rang du premier bon extrait.

| Retriever | hit@5 | MRR | Ratés |
|---|---|---|---|
| BM25 | 50,0 % | 0,41 | q03 q04 q07 q08 q10 q11 q12 q17 q18 q20 q21 q23 |
| Dense (bge-m3) | 87,5 % | 0,71 | q04 q11 q12 |
| Hybride RRF 0,5/0,5 | 87,5 % | 0,60 | q04 q11 q12 |
| **Hybride RRF 0,3/0,7** | **87,5 %** | **0,72** | q04 q11 q12 |

- BM25 seul est faible : il favorise les chunks qui **répètent** les mots de la question (souvent des passages qui parlent du sujet sans donner la réponse), ne fait pas le lien français/anglais (rapport UBS). Dans le nettoyage et tableau bcp de mots se collent -> impossible de lire ces passages.
- En poids égaux, la fusion RRF **dégrade** le classement du dense (MRR 0,71 → 0,60) : RRF favorise les documents présents dans les deux listes, et le bruit de BM25 fait remonter de mauvais candidats.
- Pondérée 0,3/0,7, la fusion égale le dense (MRR 0,72) sans gain net. On la garde pour la suite : un BM25 amélioré pourra apporter un gain sans changer l'architecture.
- Les poids ont été choisis sur ce même jeu de 24 questions : le résultat est donc légèrement optimiste.
- Les 3 ratés communs sont des **chiffres de tableaux** (rémunération, PNB, total du bilan) : le problème vient du découpage des tableaux, pas du retriever.

## 2. Génération

Chaque question passe par le pipeline complet. Trois mesures, par comparaison de texte normalisé (minuscules, sans accents ni espaces, séparateurs des grands nombres retirés) :

- **exactitude** : la ou les valeurs clés attendues apparaissent dans la réponse ;
- **citation** : au moins une page citée contient la réponse ;
- **refus** : le modèle répond « Je ne trouve pas cette information dans les extraits fournis ».

| Exactitude | Citation correcte | Refus | Réponses fausses (sans refus) |
|---|---|---|---|
| **70,8 %** (17/24) | 79,2 % | 12,5 % (3/24) | 4 : q04 q10 q16 q24 |

Réponses complètes : [`data/eval/resultats_v0.jsonl`](../data/eval/resultats_v0.jsonl).

### Analyse des échecs

| Q | Ce qui s'est passé | Cause |
|---|---|---|
| q04 | donne la rémunération **fixe** (2 300 000 €) au lieu du total (5 655 k€), en précisant bien « fixe » | retrieval : le tableau du total n'est pas retrouvé |
| q10 | donne 6 207 171 564 € présenté comme « résultat du groupe » : c'est le résultat de **Crédit Agricole S.A. entité sociale** (attendu : 7 074 M€ consolidé) | **périmètre** : mauvaise entité, et le libellé « entité sociale » de l'extrait est ignoré |
| q16 | donne 14,0 % « estimé » : c'est le ratio **cible** d'une simulation réglementaire (attendu : 14,4 % réel) | **périmètre** : cible / hypothèse confondue avec la valeur réelle |
| q24 | donne le dividende BNP seulement, pas celui d'UBS | retrieval : aucun extrait UBS dans les 5 |
| q11, q12 | refus | retrieval : chiffres de tableaux non retrouvés (refus honnête) |
| q17 | refus alors que la bonne page est retrouvée | à analyser |

Observations :
- **hit@5 != bonne réponse** : 87,5 % de hit@5 pour 70,8 % d'exactitude. Retrouver la bonne page ne suffit pas si le chunk est inutilisable (tableau sans en-tête de colonnes) ou si plusieurs chiffres proches coexistent.
- **Le principal problème n'est pas l'hallucination mais le périmètre.** Un rapport annuel contient beaucoup de chiffres qui se ressemblent : groupe / entité sociale / division, réel / cible, fixe / total, 2025 / 2024.
- Les refus sont cohérents : le modèle refuse quand le contexte ne contient pas la réponse, au lieu d'inventer.

### Problèmes rencontrés

- `gpt-oss` cite au format `【1】` ou `【1†L4-L6】` et non `[1]` : l'extraction des citations accepte les trois formes.
- Plan gratuit Mistral : clés API désactivées -> passage à Groq. Débit limité (≈ 1 requête / 20 s pour rester sous la limite de tokens par minute).

## Pistes pour la v1

1. **Tableaux** : répéter l'en-tête (années, colonnes) dans chaque chunk de tableau, ou ne pas couper les tableaux. Peut-etre par ocr ?
2. **Contexte du chunk** : rattacher le titre de section (« Comptes sociaux », « Hypothèses »…) à chaque chunk pour aider à distinguer les périmètres.
3. **Filtre par banque** quand la question la nomme ; récupérer plus de candidats pour les questions ambiguës.
4. **Prompt** : renforcer la règle sur l'entité et la distinction valeur réelle / cible.
5. **Langues** : ajouter detection langue de la question pour insister reponse dans bonne langue.
